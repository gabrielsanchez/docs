## What this tutorial covers

This tutorial demonstrates core W&B features through a simple MNIST classification example in PyTorch. You'll learn how to log hyperparameters, monitor training progress, and save models.

<Frame>
    <img src="/images/tutorials/pytorch.png" alt="PyTorch and W&B integration diagram"  />
</Frame>

The key W&B integration steps are:

1. **Initialize a run** using `with wandb.init() as run` to start tracking an experiment.

2. **Set hyperparameters** in `run.config` to keep a record of the settings used for each run.

3. **Log metrics** with `run.log()` during training to visualize model performance in real-time.

4. **Optionally track gradients** with `run.watch()` to monitor model parameters and gradients, and **save models** with `run.save()` to preserve trained models for later use.

In pseudocode, the integration looks like this:

```python
# Import the library
import wandb

# Start a new experiment
with wandb.init(project="new-sota-model") as run:
 
    # Capture a dictionary of hyperparameters with config
    run.config = {"learning_rate": 0.001, "epochs": 100, "batch_size": 128}

    # Set up model and data
    model, dataloader = get_model(), get_data()

    # Optional: track gradients
    run.watch(model)

    for batch in dataloader:
        metrics = model.training_step()
        # Log metrics inside your training loop to visualize model performance
        run.log(metrics)

    # Optional: save model at the end
    model.to_onnx()
    run.save("model.onnx")
```

## Define the experiment and pipeline

### Track metadata and hyperparameters with `wandb.init()`

Start by defining your experiment configuration. Store hyperparameters and metadata in a `config` dictionary that you'll pass to `wandb.init()`.

In this example, we specify a few key hyperparameters (epochs, batch size, learning rate) and metadata (dataset name, model architecture). This metadata helps organize runs when you later experiment with different models or datasets in the same project.

```python
config = {
    "epochs": 5,
    "classes": 10,
    "kernels": [16, 32],
    "batch_size": 128,
    "learning_rate": 0.005,
    "dataset": "MNIST",
    "architecture": "CNN"
}
```

Next, define the training pipeline. This follows a standard machine learning workflow:

1. Define the model, data loaders, and optimizer
2. Train the model with `train()`
3. Evaluate the model with `test()`

The implementation of these functions is shown below.

```python
def model_pipeline(hyperparameters):

    # Initialize W&B run
    with wandb.init(project="pytorch-demo", config=hyperparameters) as run:
        # Access all hyperparameters through run.config
        config = run.config

        # Create the model, data loaders, and optimizer
        model, train_loader, test_loader, criterion, optimizer = make(config)
        print(model)

        # Train the model
        train(model, train_loader, criterion, optimizer, config)

        # Evaluate the model
        test(model, test_loader)

    return model
```

The key W&B integration happens inside the `wandb.init()` context manager, which establishes a connection to W&B servers for tracking.

When you pass the `config` dictionary to `wandb.init()`, it automatically logs all hyperparameters, ensuring you always know which settings were used for each experiment.

Use `run.config` to access your hyperparameters within the training code. This ensures the logged values match what's actually used in your model. See the `make()` function below for examples.

```python
def make(config):
    # Create data loaders
    train, test = get_data(train=True), get_data(train=False)
    train_loader = make_loader(train, batch_size=config.batch_size)
    test_loader = make_loader(test, batch_size=config.batch_size)

    # Create the model
    model = ConvNet(config.kernels, config.classes).to(device)

    # Create loss function and optimizer
    criterion = nn.CrossEntropyLoss()
    optimizer = torch.optim.Adam(
        model.parameters(), lr=config.learning_rate
    )
    
    return model, train_loader, test_loader, criterion, optimizer
```

> *Side Note:* W&B runs in a separate process, so server issues won't crash your training. If connectivity is interrupted, you can sync data later with `wandb sync`.

### Define the data loading and model

Now, specify how the data is loaded and what the model looks like.

This part is important, but it's no different from what it would be without `wandb`,  so we won't go into detail.

```python
def get_data(slice=5, train=True):
    """Load and return a subset of the MNIST dataset."""
    full_dataset = torchvision.datasets.MNIST(
        root=".",
        train=train,
        transform=transforms.ToTensor(),
        download=True
    )
    # Equivalent to slicing with [::slice]
    sub_dataset = torch.utils.data.Subset(
        full_dataset, indices=range(0, len(full_dataset), slice)
    )
    
    return sub_dataset


def make_loader(dataset, batch_size):
    """Create and return a DataLoader for the given dataset."""
    loader = torch.utils.data.DataLoader(
        dataset=dataset,
        batch_size=batch_size,
        shuffle=True,
        pin_memory=True,
        num_workers=2
    )
    return loader
```

Since the W&B integration doesn't affect model architecture, we'll use a standard ConvNet implementation.

Feel free to experiment with different architectures. W&B will automatically track all your results at [wandb.ai](https://wandb.ai).

```python
class ConvNet(nn.Module):
    """Convolutional neural network for MNIST classification."""
    
    def __init__(self, kernels, classes=10):
        super(ConvNet, self).__init__()
        
        self.layer1 = nn.Sequential(
            nn.Conv2d(1, kernels[0], kernel_size=5, stride=1, padding=2),
            nn.ReLU(),
            nn.MaxPool2d(kernel_size=2, stride=2)
        )
        self.layer2 = nn.Sequential(
            nn.Conv2d(16, kernels[1], kernel_size=5, stride=1, padding=2),
            nn.ReLU(),
            nn.MaxPool2d(kernel_size=2, stride=2)
        )
        self.fc = nn.Linear(7 * 7 * kernels[-1], classes)
        
    def forward(self, x):
        out = self.layer1(x)
        out = self.layer2(out)
        out = out.reshape(out.size(0), -1)
        out = self.fc(out)
        return out
```

### Define training logic

Next, implement the training logic in the `model_pipeline`.

Two W&B functions are key here: `run.watch()` and `run.log()`.

## Track gradients with `run.watch()` and everything else with `run.log()`

Call `run.watch()` to automatically log your model's gradients and parameters at specified intervals (controlled by `log_freq`).

Simply call it once before starting training.

The rest of your training code follows standard PyTorch patterns: iterate over epochs and batches, perform forward and backward passes, and update weights with the optimizer.

```python
def train(model, loader, criterion, optimizer, config):
    """Train the model and log metrics to W&B."""
    # Use W&B to watch model gradients, weights, and more
    with wandb.init(project="pytorch-demo", config=config) as run:
        run.watch(model, criterion, log="all", log_freq=10)

        # Run training and track with W&B
        total_batches = len(loader) * config.epochs
        example_ct = 0  # Number of examples seen
        batch_ct = 0
        for epoch in tqdm(range(config.epochs)):
            for _, (images, labels) in enumerate(loader):
                loss = train_batch(images, labels, model, optimizer, criterion)
                example_ct += len(images)
                batch_ct += 1

                # Report metrics every 25th batch
                if ((batch_ct + 1) % 25) == 0:
                    # Log the metrics
                    run.log({"epoch": epoch, "loss": loss}, step=example_ct)
                    print(f"Loss after {str(example_ct).zfill(5)} examples: {loss:.3f}")

def train_batch(images, labels, model, optimizer, criterion):
    """Execute a single training batch."""
    images, labels = images.to(device), labels.to(device)
    
    # Forward pass
    outputs = model(images)
    loss = criterion(outputs, labels)
    
    # Backward pass
    optimizer.zero_grad()
    loss.backward()

    # Step with optimizer
    optimizer.step()

    return loss
```

The only difference is in the logging code: where previously you might have reported metrics by printing to the terminal, now you pass the same information to `run.log()`.

`run.log()` accepts a dictionary where keys identify the metrics being tracked, and the values are the corresponding data. You can also specify the training `step` to track progress over time.

> *Side Note*: For the step parameter in `run.log()`, you can use the number of examples the model has processed (which enables easier comparison across different batch sizes), batch count, or raw steps. For longer training runs, logging by `epoch` is also common.

## Define testing logic

Once the model is done training, evaluate the model on test data with a validation set, production data, or carefully curated examples.

### (Optional) Call `run.save()`

This is also a great time to save the model and final parameters to disk.

For maximum compatibility, export the model in [Open Neural Network eXchange (ONNX) format](https://onnx.ai/).

Calling `run.save()` with the filename uploads the model parameters to W&B servers, ensuring you can always match saved models to their corresponding training runs.

For advanced model management features like storing, versioning, and distributing models, explore [W&B Artifacts](https://docs.wandb.ai/models/artifacts).

```python
def test(model, test_loader):
    model.eval()

    with wandb.init(project="pytorch-demo") as run:
        # Run the model on some test examples
        with torch.no_grad():
            correct, total = 0, 0
            for images, labels in test_loader:
                images, labels = images.to(device), labels.to(device)
                outputs = model(images)
                _, predicted = torch.max(outputs.data, 1)
                total += labels.size(0)
                correct += (predicted == labels).sum().item()

            print(f"Accuracy of the model on the {total} " +
                f"test images: {correct / total:%}")
            
            run.log({"test_accuracy": correct / total})

        # Save the model in the exchangeable ONNX format
        torch.onnx.export(model, images, "model.onnx")
        run.save("model.onnx")
```

### Test hyperparameters with W&B Sweeps

We only looked at a single set of hyperparameters in this example.
But an important part of most ML workflows is iterating over
a number of hyperparameters.

You can use W&B Sweeps to automate hyperparameter testing and explore the space of possible models and optimization strategies.

Check out a [Colab notebook demonstrating hyperparameter optimization using Sweeps](https://wandb.me/sweeps-colab).

Running a hyperparameter sweep with W&B is very easy. There are just 3 simple steps:

1. **Define the sweep:** Create a dictionary or a [YAML file](/models/sweeps/define-sweep-configuration/) that specifies the parameters to search through, the search strategy, the optimization metric, and so on.

2. **Initialize the sweep:** `sweep_id = wandb.sweep(sweep_config)`

3. **Run the sweep agent:** `wandb.agent(sweep_id, function=train)`

That's all there is to running a hyperparameter sweep.
